# SmartFlow AI (v0.7)

Исследовательский цифровой двойник дорожного движения Бишкека, который строится по этапам. Это не действующая городская система: к реальным светофорам, камерам и видеопотокам проект не подключён. Сейчас в проекте четыре части:

- **Карта Бишкека** (главная страница): интерактивная 3D-карта реальных улиц и зданий (этап 1), синтетический демо-трафик по реальной сети дорог (этап 2) и виртуальные светофоры на перекрёстках, где светофор отмечен в OpenStreetMap (этап 4).
- **Эксперименты SUMO** (адрес `#sumo`, код в `sumo/`): перекрёсток Чуй × Манаса и коридор из четырёх перекрёстков проспекта Чуй в транспортном симуляторе SUMO, светофорами управляет Python через TraCI; фиксированный план, план под нагрузку, «зелёная волна» и адаптивное управление (в том числе с координацией), 30 повторов с доверительными интервалами. Подробно — [sumo/README.md](sumo/README.md) и [sumo/CORRIDOR.md](sumo/CORRIDOR.md).
- **Компьютерное зрение** (адрес `#cv`, код в `vision/`): модули анализа видео на Python и OpenCV, проверенные на реальном размеченном видео UA-DETRAC и на синтетической сцене с известной «правдой». Подробно — [vision/README.md](vision/README.md).
- **Лаборатория перекрёстка** (адрес `#lab`): учебный симулятор одного перекрёстка в браузере, описанный ниже.

Лаборатория — интерактивный симулятор управления четырёхсторонним светофорным перекрёстком: микроскопическая модель движения с поворотами и разворотами, конфликтные зоны, фазы по манёврам, два алгоритма управления, метрики и воспроизводимые эксперименты. Работает целиком в браузере, без сервера и ключей.

> Название проекта историческое. Адаптивный контроллер здесь **основан на правилах** (актуированное управление по очередям и времени ожидания), обучения в нём нет. Нейросеть в проекте одна — предобученный детектор машин YOLOX-tiny в компьютерном зрении, без дообучения.

**Технический аудит** (что подтверждено, какие дефекты исправлены, какие эксперименты выполнены) — [docs/AUDIT.md](docs/AUDIT.md). Возможные вопросы на защите и ответы — [docs/DEFENSE_QA.md](docs/DEFENSE_QA.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 145 тестов: модель перекрёстка, стиль карты, демо-трафик, светофоры и камеры города, данные SUMO и компьютерного зрения
npm run build      # статическая сборка в dist/ (base: './', можно класть на GitHub Pages)
npm run preview
```

Требуется Node.js 18+. Для карты нужен интернет: тайлы загружаются с tiles.openfreemap.org.

После запуска: `http://localhost:5173/` — карта Бишкека, `http://localhost:5173/#sumo` — эксперименты SUMO, `http://localhost:5173/#cv` — компьютерное зрение, `http://localhost:5173/#lab` — лаборатория перекрёстка.

Эксперимент SUMO считается отдельно, на Python (нужен только для пересчёта, страница работает на готовых файлах из `public/data/sumo/`):

```bash
pip install eclipse-sumo==1.28.0 traci==1.28.0 sumolib==1.28.0
cd sumo
python -m unittest discover -s tests -t .
python -m smartflow_sumo.experiment --out ../public/data/sumo    # один перекрёсток, 270 прогонов, ~18 мин на 2 ядрах
python -m smartflow_sumo.corridor --out ../public/data/sumo      # коридор, 160 прогонов, ~38 мин
```

Модули компьютерного зрения — тоже отдельно, на Python (страница `#cv` показывает готовые результаты из `public/data/cv/`):

```bash
pip install -r vision/requirements.txt
cd vision
python -m unittest discover -s tests -t .
python -m smartflow_cv.evaluate --out ../public/data/cv
python -m smartflow_cv.detrac_eval --out ../public/data/cv/cv-real-results.json   # реальное видео UA-DETRAC
```

## Карта Бишкека (этап 1)

| | |
|---|---|
| Движок | MapLibre GL JS 4.7.1 (WebGL) |
| Данные | OpenStreetMap, векторные тайлы [OpenFreeMap](https://openfreemap.org) в схеме OpenMapTiles. Бесплатно, без ключа, коммерческое использование разрешено, атрибуция обязательна |
| Атрибуция | «OpenFreeMap © OpenMapTiles Data from © OpenStreetMap contributors» — всегда видна в правом нижнем углу |
| Стиль | собственный (`src/map/style.ts`): дороги по классам, вода, зелень, здания, названия улиц и районов. Слои `poi`, `housenumber`, `aerodrome_label` не используются, поэтому компаний и заведений на карте нет |
| Высота зданий | поле `render_height` генератора тайлов: `height` из OSM, иначе `building:levels × 3,66 м`, иначе условные **5 м**. Отличить «настоящие 5 м» от «данных нет» по тайлу нельзя, это подписано в интерфейсе |
| Управление | 3D / план, приближение, вращение на 30°, «на север», «к центру» (площадь Ала-Тоо); мышь: правая кнопка или Ctrl + перетаскивание — вращение и наклон |

Код: `src/map/style.ts` (стиль, без зависимостей от браузера, покрыт тестами `tests/mapStyle.test.ts`), `src/map/MapApp.tsx` (карта и интерфейс), `src/map/map.css`. MapLibre подгружается отдельным файлом только для карты.

Ограничения этапа 1: нет данных трафика и светофоров; высоты многих зданий в OSM не заполнены (они низкие и одинаковые); подробность тайлов — до 14-го зума, дальше геометрия масштабируется; карта не работает без интернета и без WebGL.

## Демо-трафик (этап 2)

**Синтетические данные.** Это не реальное движение: начало и конец каждой поездки выбираются случайно. Путь — кратчайший по времени по реальной сети дорог OpenStreetMap.

```
scripts/build-road-network.mjs     OSM (Overpass) → public/data/bishkek-roads.json — запускается вручную, не в браузере
src/traffic/network.ts             загрузка и проверка файла сети, локальные метры
src/traffic/routing.ts             генерация маршрутов: Дейкстра по времени, профиль скорости
src/traffic/fleet.ts               движение машин по маршрутам, без карты и отрисовки
src/traffic/trafficLayer.ts        только отрисовка на MapLibre (GeoJSON-источник, точки и силуэты)
src/traffic/controller.ts          связывает части: загрузка → маршруты → движение → отрисовка
src/traffic/TrafficPanel.tsx       интерфейс: старт/пауза, сброс, скорость 1–10×, число машин, дорожный граф
```

- **Дорожная сеть.** Центр Бишкека, рамка 74,54–74,68° в. д. × 42,83–42,90° с. ш. Классы дорог motorway…unclassified, без жилых улиц и проездов: около 1000 узлов, 1350 участков, 330 км, 170 КБ. Перекрёсток — узел OSM, общий для нескольких линий. Учтены односторонние улицы и кольца. Оставлена крупнейшая сильно связная часть, поэтому из любого узла можно доехать в любой. Данные © OpenStreetMap contributors, ODbL. Обновить сеть: `node scripts/build-road-network.mjs` (нужен доступ к Overpass API).
- **Маршруты.** Случайная пара узлов не ближе 1,5 км друг от друга, путь — кратчайший по времени. Условные скорости: магистраль 55, primary 50, secondary 45, tertiary 40, unclassified 30 км/ч. На поворотах от 90° скорость снижается до 18 км/ч. Новая поездка начинается там, где закончилась предыдущая. Всё детерминировано по seed 2026.
- **Движение.** Разгон 1,5 м/с², торможение 3 м/с², дистанция до машины впереди на той же улице. На двусторонних улицах машины смещены к правому краю.
- **Чего нет.** Приоритета между направлениями на перекрёстках, перестроений, реальных объёмов движения. Машины разных направлений внутри перекрёстка не уступают друг другу. Это не модель пробок. Светофоры (только где они есть в OSM) — см. этап 4.
- **Производительность.** Не больше 1000 машин. Отрисовываются только машины в пределах экрана, не больше 800. Слой обновляется ~30 раз в секунду. При зуме меньше 12 слой скрыт, а модель продолжает считаться. Шаг модели для 1000 машин занимает около 2 мс.
- **Час пик** (переключатель «Спрос» или ссылка `#rush=morning` / `#rush=evening`). Тоже синтетика: ¾ поездок утром едут с окраин в центр (2,2 км от площади Ала-Тоо), вечером обратно; 60 % из них начинаются на въездах в город — концах магистралей на границе графа (проспект Чынгыза Айтматова на юге, Жибек Жолу на востоке и другие). По умолчанию 3000 машин. На 10 seed по 20 минут модели средняя скорость при Baseline 24,6 км/ч, в адаптивном режиме 28,8 км/ч: +4,2 км/ч (95 % ДИ +3,8…+4,6), лучше в 10 из 10 (`scripts/rush-check.ts`, `public/data/city/rush-check.json`). Это иллюстрация на синтетике, а не измерение реальных пробок.
- **Ошибки.** Если файл сети не загрузился или повреждён, панель показывает причину и кнопку «Повторить». Карта при этом работает.

## Светофоры города (этап 4, часть 1)

Это исследовательская модель, а не городская система: к реальным светофорам и камерам проект не подключён.

```
scripts/build-signals.mjs        OSM (Overpass) → public/data/bishkek-signals-osm.json: только факты, без выводов
src/signals/inventory.ts         факты OSM + дорожный граф → светофорные объекты (подходы, полосы, переходы)
src/signals/plan.ts              виртуальный план фаз по геометрии подходов (приближение)
src/sim/signalMachine.ts         автомат «зелёный → жёлтый 3 с → все красные 2 с»: общий с лабораторией
src/signals/runtime.ts           режимы Baseline / адаптивный / ручной, защитные ограничения, журнал решений
src/signals/observe.ts           очереди по фазам из демо-трафика (синтетика)
src/signals/system.ts            все светофоры города; связь въездных участков графа с фазами
src/signals/signalLayer.ts       слой MapLibre: кластеры, сигналы въездов, узлы OSM
src/signals/SignalPanel.tsx      панель выбранного светофора; src/map/LayersPanel.tsx — слои, фильтры, легенда
```

- **Данные.** В рамке центра Бишкека в OSM 327 узлов `highway=traffic_signals` и 2083 пешеходных перехода, из них 721 регулируемый (выгрузка 21.10.2026). Обновить: `node scripts/build-signals.mjs` (нужен доступ к Overpass API).
- **Где стоят светофоры.** Только там, где светофор есть в OSM. Узел OSM относится к ближайшей развилке графа (≥ 3 участков) не дальше 40 м, светофор у перехода — не дальше 30 м. Узлы графа, связанные короткими участками (≤ 45 м), объединяются: перекрёсток с разделёнными проезжими частями — один объект. Получилось 191 объект: 190 рабочих, у 1 в графе меньше двух въездов («данные недоступны»). Ещё 61 светофор OSM — пешеходные вне перекрёстков, 15 — на улицах, которых нет в графе. Проверка согласованности: 539 из 721 регулируемых переходов OSM лежат в 50 м от найденных объектов.
- **Подходы.** Внешние участки объекта, объединённые по азимуту (≤ 25°) и названию улицы. Число полос — из тега `lanes` (у двусторонних улиц — половина), «?» — тег не заполнен.
- **Фазы — приближение.** Программ реальных светофоров в открытых данных нет. Противоположные въезды (180° ± 40°) едут в одной фазе, главная дорога первой. Зелёный — по классу дороги и числу полос, 10–60 с. Цикл 60–100 с. Если по геометрии фаза одна, добавляется виртуальная пешеходная фаза 15 с. Сдвиг цикла у каждого светофора свой.
- **Режимы.**
  - Baseline — фиксированный план.
  - Адаптивный — контроллер лаборатории: правила по очередям и ожиданию, без машинного обучения. Он работает на синтетических очередях демо-трафика. Это отдельная реализация на TypeScript, её параметры отличаются от контроллера в SUMO; доказательные числа — только из SUMO.
  - Ручной — фаза держится до команды оператора.

  Во всех режимах действуют одни правила: минимальный зелёный 8 с, жёсткий максимум 120 с, переход только через жёлтый и «все красные», зелёный горит одной фазе. При ошибке адаптивного контроллера светофор переходит на фиксированный план и записывает причину в журнал.
- **Трафик.** Машины останавливаются на красный в 12 м до узла графа. На жёлтый они останавливаются, если успевают, иначе проезжают. Приоритета между направлениями внутри перекрёстка по-прежнему нет.
- **Интерфейс.**
  - Слой с кластеризацией на мелком масштабе; на зуме ≥ 15 — сигнал каждого въезда, на зуме ≥ 16 — узлы OSM как факты.
  - Панель светофора: фазы, время до переключения, очереди, режим, журнал решений, ссылки на узлы OSM. Для Чуй × Манаса — ссылка на эксперимент SUMO.
  - Фильтры по состоянию и режиму, легенда, переключатель «Baseline / адаптивный» для всех светофоров.
- **Иллюстрация, не доказательство.** Синтетический трафик, 1000 машин, 30 минут модели, seed 2026:

  | Режим | Поездки | Средняя скорость |
  |---|---|---|
  | без светофоров | 3431 | 41,9 км/ч |
  | Baseline | 2795 | 34,5 км/ч |
  | адаптивный | 3233 | 40,4 км/ч |

  Поток в демо-слое редкий, поэтому адаптивные правила легко выигрывают у плана, рассчитанного «на глаз». Доказательное сравнение — в эксперименте SUMO.
- **Тесты:** `tests/signals.test.ts` (24) и `tests/cityTraffic.test.ts` (3). Они проверяют:
  - объекты появляются только там, где светофор есть в OSM;
  - разделённые проезжие части объединяются в один объект;
  - подходы и полосы определяются верно;
  - фазы, цикл и сдвиг считаются правильно;
  - два часа случайных переключений режимов без нарушений: зелёный 8–120 с, жёлтый 3 с, «все красные» 2 с;
  - ручной режим держит фазу и отпускает её на жёстком максимуме;
  - при ошибке контроллера включается фиксированный план;
  - на реальных данных: каждый узел OSM учтён, у Чуй × Манаса 4 подхода и 4 узла светофора;
  - в демо-трафике никто не въезжает на красный и город не «запирается».

## Камеры и загруженность (этап 4, часть 2)

Камеры виртуальные: расставлены по правилам модели, к реальным камерам и видеопотокам проект не подключён. У каждой камеры в интерфейсе виден режим данных: «синтетические данные» или «визуальный макет». Режимы «тестовое видео» и «реальный источник» в браузерной части не используются.

```
src/cameras/geometry.ts     пересечение линии траекторией (с направлением), время пересечения, скорость на участке
src/cameras/placement.ts    расстановка по правилам (ниже)
src/cameras/system.ts       обработка кадров синтетического трафика: метрики, события, настройки
src/cameras/cameraLayer.ts  слой MapLibre: тип — цвет, полый кружок — макет, конус — направление обзора
src/cameras/CameraPanel.tsx панель камеры: тип, статус, источник, метрики, события, чувствительность и порог уверенности
src/traffic/congestion.ts   загруженность участков; congestionLayer.ts — цветовая карта
```

| Тип | Где стоит | Что считает | Как |
|---|---|---|---|
| Поток (109) | главный въезд светофоров с магистралью, 30 м до стоп-линии | поток, средняя скорость, плотность, занятость зоны, очередь, затор | пересечения линии подсчёта; скорость в момент пересечения даёт симулятор; затор — средняя скорость за 2 мин ниже порога **и** очередь ≥ 5 |
| Скорость (51) | середина участков магистралей ≥ 300 м, не ближе 700 м друг к другу | скорость каждой машины, превышение | время между двумя линиями в 100 м (участковый метод), время пересечения интерполируется внутри шага; ограничение — условная скорость класса дороги в модели, допуск настраивается |
| Сплошная линия (12) | двусторонние въезды к светофорам | пересечение оси дороги на последних 30 м до стоп-линии | отрезок траектории пересекает линию в координатах дороги; заезд мельче порога — «недостаточно данных», а не нарушение |
| Ремень (5) | крупные перекрёстки | ничего | визуальный макет: модели нет, результат всегда «невозможно определить» |

- **Честность метрик.** Без данных показатель — «—» или «недоступно», а не ноль. Очередь видна только у камер на въезде к светофору. Скорость не определяется, если машина появилась внутри участка измерения.
- **Синтетический трафик.** Машины не перестраиваются и держатся правее оси, поэтому у камер линии событий нет. Детектор проверен тестами на заданных траекториях.
- **Приватность.** События анонимны: номер машины в пределах сеанса, без номеров и изображений. Каждое событие помечено как предварительное, а не юридическое заключение.
- **Загруженность** — доля условной свободной скорости по машинам на участке, сглаженная за минуту. Есть 4 уровня; участки без машин не окрашиваются. Это показатель модели, а не реальных пробок.
- **Тесты** `tests/cameras.test.ts` (16):
  - геометрия пересечений и направлений; касание без перехода — не пересечение;
  - скорость равна истинной при шаге кадра 0,1, 0,7 и 2 с;
  - превышение учитывает допуск; без въезда на участок скорость не выдумывается;
  - подсчёт потока; при отсутствии машин метрики пустые;
  - линия: события и «недостаточно данных»;
  - ремень — макет без оценок;
  - камера без данных и выключенная камера;
  - анонимность;
  - реальная расстановка;
  - 10 минут городского трафика: скорости правдоподобны, никто не пересёк линию.

## Эксперимент SUMO (этап 3)

Первый инженерный эксперимент: перекрёсток проспекта Чуй и улицы Манаса в транспортном симуляторе [SUMO](https://eclipse.dev/sumo/) 1.28.0. Светофором управляет Python через TraCI. Код, описание модели, допущения и инструкция — в [sumo/README.md](sumo/README.md).

- **Модель.** Один узел, подходы по реальным азимутам и числу полос из OSM: Чуй с запада 3 полосы, с востока 2, Манаса с севера 2, с юга 1. Запрет правого поворота с юга (OSM, отношение 2700742) соблюдён. Назначение полос, спрос и план фаз — допущения. Это **не** копия реального перекрёстка.
- **Контроллеры.**
  - Фиксированный цикл по Уэбстеру (97 с, рассчитан на среднюю нагрузку).
  - Тот же расчёт под каждую нагрузку (65 / 97 / 120 с) — самый сильный фиксированный соперник.
  - Адаптивный — актуированное управление по очередям и ожиданию, без машинного обучения.

  Все работают через общий страж: минимальный зелёный 8 с, жёлтый 3 с, «все красные» 2 с, конфликтующие зелёные невозможны.

  - 3 нагрузки × 30 seed × 3 контроллера = 270 прогонов по 60 минут.

## Компьютерное зрение (этап 4, часть 4)

Отдельный пакет на Python и OpenCV (`vision/smartflow_cv`): `vehicle_detection`, `vehicle_tracking`, `speed_estimation`, `seatbelt_assessment`, `lane_crossing_detection`, `traffic_density_estimation`. Каждый модуль выключается отдельно и вместо числа сообщает статус, если данных нет. Вычисления — на CPU вне браузера.

- **Проверка на реальном видео** — публичный размеченный набор UA-DETRAC, 10 видео с неподвижных камер, 3000 кадров. Классический детектор непригоден: F1 9–12 %, на каждый верный ответ — около 11 ложных. Нейросеть YOLOX-tiny (предобучена на COCO, без дообучения, запускается через OpenCV на CPU) даёт точность 91–93 %, полноту 74 %, F1 82 %. Счёт машин на линии ошибается на 2–4 % за 10 видео. Кадры набора в проект не копируются.
- **Проверка на синтетической сцене** с известной «правдой» — там, где у реального набора нет разметки: скорость и сплошная линия. Прямая дорога, камера на высоте 12 м, машины по модели IDM, очередь у светофора, перестроения через сплошную, превышения скорости. Шесть условий съёмки, 2 seed.
- **Скорость** считается по калибровке (гомография «пиксели → метры») и времени, а не по размеру машины в кадре. Без калибровки — «нет калибровки».
- **Сплошная линия** задаётся в метрах на дороге. Неглубокий заезд, край линии, потерянный трек и скачок рамки дают «недостаточно данных», а не нарушение.
- **Ремень:** модели нет, результат всегда «невозможно определить». Готовы интерфейс для специализированной модели и проверка качества кадра.
- **Тестовое видео:** `python -m smartflow_cv.run --video … --calibration … --config …` обрабатывает запись и выдаёт агрегаты и анонимные события. Кадры, лица и номера не сохраняются.

## Модель

**Геометрия.** 4 въезда по 2 полосы. Стоп-линия отнесена на 6 м от края пересекаемой дороги (радиус бордюра), поэтому радиус правого поворота 7,75 м, левого 14,75 м. Разворот построен как полуокружность радиусом 3,5 м: это половина расстояния между левой полосой въезда и правой полосой выезда. Для реального легкового автомобиля это тесно, модель здесь упрощена.

**Маршруты.** Путь = въездная полоса + соединитель + полоса выезда. Соединитель — кубическая кривая Безье, повторяющая дугу окружности (k = 0,5523·R), у «прямо» — отрезок. Путь разбит на точки через 0,25 м с направлением и кривизной. Скорость ограничена боковым ускорением 2,5 м/с²; заранее рассчитан профиль торможения перед кривой (≤ 2 м/с²). Ограничение проверяется по всему кузову.

**Разметка полос** (настройка):
- *только налево* — левая полоса: налево и разворот; правая: прямо и направо;
- *налево + прямо* — левая: налево, разворот, прямо; правая: прямо и направо.

Перестроений нет: полоса выбирается при появлении машины.

**Генерация.** На каждое прибытие делается ровно три обращения к ГПСЧ своего въезда: интервал, манёвр и полоса. Поэтому спрос не зависит от контроллера и настроек и одинаков в парах эксперимента. Доли манёвров задаются для каждого въезда и нормируются. Разворот разрешается отдельно для каждого въезда; если он запрещён, его доля не учитывается.

**Конфликтные зоны.** Для каждой пары маршрутов перебираются положения обоих автомобилей на соединителях (шаг 0,5 м) и проверяется пересечение прямоугольников 4,5 × 1,8 м с запасом 0,3 м. Зона пары — диапазон положений, при которых кузова могут пересечься. Типы зон: пересечение, слияние в одну полосу выезда, расхождение из одной полосы.

**Допуск на въезд.** Решение принимается на расстоянии v²/(2·2,5) + v·1 с + 2 м до стоп-линии. Допуск даётся, если выполнены все условия:
1. сигнал маршрута разрешающий;
2. въезжает первой в своей полосе;
3. никто из конфликтующих не держит общие зоны;
4. для уступающего манёвра у каждого защищённого конфликтующего потока время прибытия к зоне больше, чем время освобождения зоны + 1,5 с.

Получив допуск, машина держит все зоны своего пути и освобождает каждую, проехав её. Если на жёлтом машина может остановиться, допуск снимается. Первая стоящая уступающая машина может завершить поворот в первые 0,5 с жёлтого.

**Почему нет взаимных блокировок.** Машина с допуском никогда не ждёт зону. Её лидер тоже имеет допуск или уже на полосе выезда, а у полос выезда нет затора ниже по потоку. Все зоны берутся разом, поэтому ситуации «держу одну и жду другую» не бывает.

**Фазы.**

| Режим | Фазы | Налево / разворот |
|---|---|---|
| с уступкой | С–Ю, В–З | разрешены на зелёный, уступают встречному прямому |
| отдельная фаза | левые С–Ю → прямые С–Ю → левые В–З → прямые В–З | защищены в своей фазе (встречные левые не пересекаются) |

План строится автоматически: маршрут защищён, если не конфликтует с уже защищёнными в фазе, иначе уступает. `validatePlan` проверяет, что в одной фазе нет двух защищённых конфликтующих маршрутов.

**Контроллеры.** Фиксированный: зелёный С–Ю, В–З и левых фаз. Адаптивный (правила, не ML): минимальный и максимальный зелёный, разрыв потока в зоне детектора 40 м, давление = очередь + ожидание / вес; фазы без спроса пропускаются.

**Метрики.** Ожидание — время со скоростью < 0,5 м/с, включая ожидание въезда в модель. Задержка — время в пути минус время свободного проезда по профилю скорости маршрута. По каждому манёвру считаются: обслужено, среднее ожидание, текущая и максимальная очередь.

**Проверки безопасности на каждом шаге**, независимо от логики допуска:
- две машины конфликтующих маршрутов одновременно в общей зоне;
- геометрическое пересечение кузовов (теорема о разделяющей оси);
- пересечение стоп-линии на красный;
- аварийные ограничения позиции;
- минимальный зазор.

## Тесты

`npm test` — 54 теста (≈ 50 с):
- **геометрия:** 20 путей непрерывны и гладкие, конечное направление верное, скорость на кривых ограничена;
- **конфликты:** таблица симметрична; найдены пересечения, слияния и расхождения; нет ложных конфликтов (встречные прямые, правые, левые);
- **фазы:** в обоих режимах, с разворотами и без, нет одновременно защищённых конфликтующих потоков, каждый маршрут обслуживается, запрещённый разворот не попадает в план;
- **безопасность:** 2 режима левого × 2 разметки × 2 контроллера × 2 seed × 20 мин со смешанным потоком — ноль нарушений по всем проверкам, зазор > 1 м;
- **красный:** машины всех манёвров стоят до стоп-линии; на каждом шаге зелёные защищённые маршруты не конфликтуют;
- **повороты:** все манёвры завершаются в нужном направлении, время внутри перекрёстка < 30 с, боковое ускорение ≤ 1,2 от допустимого;
- **блокировки:** высокая нагрузка 1 ч — каждые 10 мин обслуживается каждый манёвр;
- **воспроизводимость:** одинаковый seed даёт одинаковый результат, спрос одинаков для контроллеров, доли манёвров соответствуют заданным, сохранение машин.

## Известные ограничения и наблюдения

- Нет перестроений, пешеходов и разных типов транспорта.
- Удержание зоны с момента допуска (за 40–55 м до линии на скорости) консервативно: это снижает пропускную способность разрешённого левого.
- При сильном встречном потоке (≥ 700–800 авт/ч на въезд) разрешённый левый почти не обслуживается, очередь растёт неограниченно. Это ожидаемое поведение; нужна отдельная фаза.
- Общая полоса «налево + прямо» при отдельной левой фазе резко снижает пропускную способность: прямые и левые блокируют друг друга. Это реальный эффект, интерфейс о нём предупреждает.
- В режиме 4 фаз адаптивный контроллер в части сценариев уступает фиксированному. Правила давления рассчитаны на 2 фазы; результат не подгонялся.
- Около 5% защищённых машин за прогон ждут уступающую машину, которая уже заняла зону, в основном при смене фаз. Это безопасно, но приоритет не абсолютный (см. «priorityBlocked» в метриках).
- Метрики считаются с t = 0, без разогрева. Эксперимент выполняется в основном потоке.
